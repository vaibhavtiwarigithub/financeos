# Paper Signal Dedup and Capital Rotation Review

> Completed: 2026-07-22
> Reviewed commits: `cefcffc9`, `6880f728`, `7c5f48fd`

## Findings And Fixes

1. **Critical - incomplete paper rotation was enabled in production.** The US
   paper row had `rotation_paper_execute_enabled=true`, although required P1
   cost/tax, turnover, fresh source price, correlation, and post-swap replay
   gates are not implemented. The flag was reset to false immediately.
   Migration `20260722185000` now enforces false with a database constraint;
   shadow measurement remains enabled.
2. **Critical - rotation could mutate the book without owning the signal
   claim.** The old RPC wrote sell/buy legs and only later attempted a
   status-only signal update without checking affected rows or `claim_run_id`.
   The old RPC was removed. Its replacement verifies the exact run-owned claim,
   returns `p1_guardrails_incomplete`, and contains no money or ledger writes.
3. **High - dedup happened after `limit(10)`.** Three same-symbol rows could
   crowd seven unique candidates out of the query window. PaperTrader now loads
   up to 1,000 same-day rows with an exact count, fails closed on truncation,
   deduplicates, and then applies the per-market unique-symbol limit.
4. **High - discarded duplicates remained pending.** They could be retried by
   a later cron and create repeated pyramid attempts. Lower-ranked duplicates
   now transition from `pending` to `superseded` with a compare-and-set update.
5. **High - persistence counted the current shadow event.** Default
   two-run persistence could pass on the first run. It now counts distinct
   prior `run_id` values and excludes the current run.
6. **Medium - query failures looked like no opportunities.** Stale-expiry,
   candidate, supersession, position, score, cooldown, daily-cap, and
   persistence query errors now fail closed with explicit diagnostic reasons.
7. **Medium - per-run rotation counters crossed markets.** A US rotation could
   consume India's cap. Counters are now market-local.
8. **Medium - hedge positions were eligible rotation sources.** Both shadow and
   future execution evaluation now read only `position_role='alpha'`.
9. **Build regression - system map BOM.** A newer documentation commit
   reintroduced a UTF-8 BOM and broke the architecture drift test. Removed.

## Reviewed Non-Issues

- Dedup before `isSymbolBlocked` is correct because blocking is symbol/market
  policy, not signal-row policy.
- Pre-market-column fallback is US-only and still excludes India asset rows.
- Normal fills remain protected from duplicate execution by the
  `pending -> claiming` compare-and-set plus transactional fill RPC.
- `rotReason='not_attempted'` was not a reachable persisted result: every branch
  either returned a reason or captured an exception. It is diagnostic only.
- A successful rotation `continue` would be correct only when the RPC consumed
  the claim atomically. P1 is now unreachable, so this branch cannot currently
  claim success.

## Production Proof

- US/India, paper/live rotation flags: all false.
- Constraint: `rotation_paper_execute_enabled = false`.
- Old 15-argument money-moving RPC: absent.
- New 16-argument RPC: service-role only, anon denied, no paper money writes.
- P0 shadow rows and audit ledger remain available.
