Expected benefit: measure their forecasting value using existing allowances; no assumed investment improvement. ## Contract

The existing API council remains available. Subscription mode queues frozen jobs instead of invoking inference providers. Hybrid mode combines selected API participants (for example DeepSeek) with selected Claude/Codex membership workers, with a hard maximum of five total council members. Owner registers up to five workers, each with a family, expected model, and revocable random Kairos credential stored only as a SHA-256 digest. This credential grants only claiming that worker's jobs and submitting its results; it is not a provider login and cannot read portfolios or execute trades.

The shared near-threshold collector freezes evidence once. Subscription batches reference ordinary council runs; synthetic batches have no observation/run linkage and never enter IC. Jobs are leased atomically, have a hard batch deadline, and accept one immutable result per worker/round. Every result must bind packet hash, job, lease, expected model and valid citations. Retries of the same accepted result return success; conflicting or expired results fail. All selected members must finish a round before a subsequent debate round opens. Debate peers are anonymous and final consensus is a deterministic median; no paid orchestrator is called.

Async subscription forecasts record their actual availability time at result submission. Existing observation-time labels cannot grade a delayed subscription forecast. The separate `forecast_available_close_v1` evaluator labels the first valid regular-session close strictly after availability and then h2/h5/h10/h20 complete-session benchmark-neutral returns. It fails closed for missing symbol/benchmark closes and calendar years not represented by the maintained market calendar. It measures gross close-to-close price returns, not execution P&L. The original decision-time evaluator remains unchanged. Historical forecast rows are immutable; legacy subscription rows without a trustworthy availability timestamp are excluded from this delayed cohort and shown with unknown availability. Never relabel synthetic tests as forecasts.

Hybrid makes one independent API call per selected API member; it does not call an API orchestrator or run metered API debate. Subscription workers may debate within their own worker group. The final numeric score is a deterministic median across the complete selected roster; it is withheld if any selected member fails. API calls remain subject to the hard daily USD budget. No score feeds trading.

## Implementation and migration

The subscription queue and API/subscription hybrid require the worker/batch/job tables, RLS and invoker RPCs for atomic claim/submission/progression. Config defaults preserve API mode and disabled state. Owner routes register/revoke workers and create synthetic batches. A separate bearer-authenticated worker route exposes claim and submit. Node worker runs official signed-in Codex or Claude CLI and validates structured output. The worker must be scheduled or started by the owner; its machine must be awake and connected. The available Claude web Routine trigger returns a run/session reference, not a structured result callback into Kairos. The currently inspected Claude Routine is paused, has no project connector, and its test prompt expects an older schema. Therefore Claude cloud Routine execution is not integrated; do not call it a worker until a supported authenticated connector is built and contract-tested.

Subscription sessions remain in the provider client. Kairos never reads or stores those credentials. No fallback to a paid API. Missing quota, authentication, model evidence or a deadline gives a visible failed/expired job, not an invented score. Token counts are nullable when unavailable; subscription usage is not presented as free inference or a fabricated API dollar charge.

## Owner setup (local membership worker)

1. In Settings → AI & keys → Multi-LLM research council, choose **Subscription workers**. Register a worker with an exact model ID supported by the installed signed-in client. Registration returns a one-time `kcw_…` credential; copy it directly to a private local config file, not a prompt, chat, repository, or shared cloud secret store.
2. Create a private JSON config containing only `origin` (the Kairos HTTPS origin, no path) and `token`. Keep the file outside the checkout, for example under `%LOCALAPPDATA%\Kairos\council-worker.json`; restrict it to the Windows account. Do not paste the token into a shell command, since command history can persist it.
3. With Codex CLI signed in to ChatGPT, run `node scripts/council-subscription-worker.mjs <private-config-path>` once to claim and process one job. To test, select the worker in Kairos, queue a synthetic test, then run `node scripts/council-subscription-worker.mjs <private-config-path> --synthetic-only`. A missing CLI login is shown as a failed test, not silently replaced by an API call.
4. For recurring collection, schedule this command locally at a modest interval (for example every 5 minutes during expected research windows). The app queues at most its configured daily symbol limit; when no job exists, the runner exits. Windows Task Scheduler runs only while the machine/session conditions you configure permit. No supported cloud executor currently consumes personal ChatGPT or Claude memberships.
5. Claude Code Pro works by the same local process only after `claude auth status` confirms an authenticated Claude subscription session. The owner session was verified on 2026-10-12. The registered Sonnet 4.6 worker has not passed its production synthetic test; do not use it for real-symbol collection until Settings shows a completed synthetic batch. Revoke a worker in Settings to invalidate its credential immediately.
