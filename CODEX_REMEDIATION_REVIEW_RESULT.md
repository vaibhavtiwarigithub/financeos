# Scoped Adversarial Remediation Review — 2026-07-10

## 1. Executive verdict

**Not clean. Keep `AUTONOMOUS_LIVE_ENABLED=false`.** Claude fixed several real defects: the manual and autonomous callers now share `executeApprovedOrder`, signal-query errors are loud, the US/India NAV sources are separated, fold-local calibration removes the original coefficient leakage, route authorization improved, and the PIN is hashed. However, the implementation still contains multiple live-money blockers.

The most serious results are:

- migration 143 still does not reproduce the live-auto schema and leaves a `SECURITY DEFINER` money-budget RPC executable by `PUBLIC` on a clean database;
- autonomous selection now reads a real `agent_signals.confidence` column, but ResearchAgent never writes it, so every normal signal becomes confidence `0` and autonomy still silently gate-blocks everything;
- the autonomous gateway accepts autonomy level L3 and never checks that a signal's strategy version is `live_approved`;
- India sizing still treats `live_auto_max_per_order_usd` as an INR cap;
- live exits can duplicate SELL orders every 30 minutes, stop operating exactly when auto/kill switches are turned off, and do not exist for India;
- cancel-on-kill cancels protective SELLs as well as entry BUYs and marks a cancellation final before broker reconciliation;
- the Robinhood “serverless” adapter bypasses the official Trading MCP and sends an MCP OAuth token to an undocumented/private REST API.

The 142 unit tests pass, but no test invokes `executeApprovedOrder`, `runAutonomousLive`, `runLiveExitMonitor`, broker submit/reconcile, or the SQL RPC. `npm run build` did not complete within 184 seconds and produced no result, so a green release build was not verified.
